- 의존 구조 = 어떤 단어가 어떤 단어에 의존하는지 표현
- 구조적 모호성 = 같은 문장이 여러 묶임, 연결 방식을 허용하는 현상

## 2. 의존 구문 분석의 기본 개념

- Head(중심어) = 특정 관계에서 중심이 되는 단어
- Dependent(의존어) = 그 head에 의존하는 단어
- 관계 라벨 = 연결의 문법적 역할.
- ROOT = 문장 전체의 중심 단어를 연결하는 가상의 노드
- 트리뱅크 = 문장에 정답 구분 구조를 주석으로 달아 놓은 데이터 모음
- Universal Dependencies(UD) 여러 언어의 품사와 의존 관계를 일관된 기준으로 주석화하려는 프로젝트

ex. `I ate fish`

```json
ROOT ──root──→ ate
                ├──nsubj──→ I
                └──obj────→ fish
```

기본 의존 트리의 조건

- 각 실제 단어의 **head는 정확히 하나**입니다.
- 하나의 head는 **여러 dependent**를 거느릴 수 있습니다.
- 모든 단어가 ROOT에서 이어지는 **하나의 연결된 구조**에 포함됩니다.
- 화살표를 따라 출발점으로 돌아오는 **순환이 없어야** 합니다.
- 보통 ROOT에는 **문장 중심 단어 하나**가 직접 연결됩니다.

기억할 점

- head는 문법적 주어를 뜻하지 않는다
- 관계에 따라 역할이 달라진다 (어떤 단어는 head이자 dependent가 될 수 있다)

## 3. 의존 관계를 판단하는 단서

- 단어 쌍의 결합 적합성 = 이 두 단어가 이런 관계를 맺는 것이 자연스러운가?
- 의존 거리 = 두 단어가 얼마나 떨어져 있는가?
- 중간에 끼여있는 요소 = 사이에 어떤 단어, 문장부호, 절의 경계가 있는가?
- Head의 결합가 = 이 중심어는 보통 어떤 참여자들을 취하는가?

⇒ 핵심!! 어느 단서 하나만으로 정답을 결정하지 않고 함께 고려해야 한다

| 라벨         | 의미                              | 예문과 연결                                  |
| ------------ | --------------------------------- | -------------------------------------------- |
| **`nsubj`**  | 명사적 주어                       | **Mina** sleeps. → `sleeps → Mina`           |
| **`obj`**    | 목적어, 보통 직접목적어           | I read a **book**. → `read → book`           |
| **`iobj`**   | 간접목적어                        | Mina gives **Jisu** a book. → `gives → Jisu` |
| **`amod`**   | 형용사 수식어                     | a **small** cat → `cat → small`              |
| **`advmod`** | 부사 수식어                       | sleeps **quietly** → `sleeps → quietly`      |
| **`det`**    | 한정사                            | **the** cat → `cat → the`                    |
| **`nummod`** | 수량을 나타내는 수식어            | **three** books → `books → three`            |
| **`root`**   | 가상 ROOT와 문장 중심 단어의 관계 | Mina **sleeps**. → `ROOT → sleeps`           |

전치사나 수동태가 포함된 경우 만날 수 있는 관계

| 라벨             | 의미                                       | 예문과 연결                            |
| ---------------- | ------------------------------------------ | -------------------------------------- |
| **`nsubj:pass`** | 수동태의 명사적 주어                       | The **book** was read. → `read → book` |
| **`aux`**        | 조동사                                     | Mina **can** swim. → `swim → can`      |
| **`aux:pass`**   | 수동태 조동사                              | The book **was** read. → `read → was`  |
| **`nmod`**       | 명사를 꾸미는 명사적 요소                  | the girl with a **bag** → `girl → bag` |
| **`obl`**        | 술어에 연결되는 장소·도구 등의 명사적 요소 | slept on the **sofa** → `slept → sofa` |
| **`case`**       | 전치사·격 표지 등                          | on the sofa → `sofa → on`              |

## 4. 투사성과 비투사성

투사성(projectivity) = 의존 관계를 문장의 단어 순서 위에 그렸을 때, 연결선이 교차하는지와 관련된 성질 → 단어들간의 연결이 단어들의 순서와 어떻게 어울리는가를 본다

투사적 구조 = 의존선이 서로 교차하지 않는 구조

판단할 때 지켜야하는 조건

- 단어를 원래 문장 순서대로 놓기
- 가상 ROOT는 맨 왼쪽에 놓는다
- 모든 의존선을 단어 위쪽에 그린다

⇒ 여기서 선들이 교차하지 않으면 투사적, 교차하는 선이 있으면 비투사적

+) 교차와 순환

- 교차 : 문장 순서 위에 그린 두 의존선이 가로지르는 것
- 순환 : 화살표를 따라가면 출발한 단어로 되돌아오는 것

주의) 비투사적 트리도 올바른 의존트리일 수 있따. 선이 교차한다는 것 ≠ 순환이 생긴다는 것

> 올바른 트리 = 각 단어의 head가 하나이고 순환이 없는 트리

정리

- 투사적 구조 = 단어를 원래 순서대로 놓았을 때 의존선이 교차하지 않음
- 비투사적 구조 = 서로 교차하는 의존선이 존재
- 중첩 = 한 선이 다른 선을 감싸는 것은 교차가 아님
- 장거리 의존 관계 = 멀리 연결된다는 이유만으로 비투사적인 것은 아님
- 교차와 순환 = 교차는 선의 배치, 순환은 화살표를 따라 출발점으로 돌아오는 것

## 5. 전이 기반 의존 구문 분석

: 파서가 작은 동작을 반복해서 의존 트리를 만드는 방법

> 파서 = 구문 분석을 통해 얻은 계층적 정보를 바탕으로 컴퓨터가 직접 사용할 수 있는 형태의 내부 데이터 구조를 생성하고 반환

전이 = 현재 상태를 다음 상태로 바꾼다

>

파서가 관리하는 3가지 정보

- 스택 : 현재 처리 중인 단어 & 부분 트리를 보관 | 시작 상태 : `[ROOT]`
- 버퍼 : 아직 스택으로 가져오지 않은 단어를 보관 | 시작 상태 : `[I, ate, fish]`
- 아크 집합(Arcs) : 지금까지 만든 의존 관계를 저장 | 시작 상태 : `{}` ← 비어있음

+) 스택은 오른쪽이 맨 위, 버퍼는 왼쪽이 맨 앞

1. 시작

```json
스택:  [ROOT]              ← 오른쪽에 단어를 쌓음
버퍼:  [I, ate, fish]      ← 왼쪽부터 단어를 가져옴
아크:  {}
```

1. SHIFT → 버퍼 맨 앞의 단어를 스택 맨 위로 옮김

```json
스택:  [ROOT, I]
버퍼:  [ate, fish]
아크:  {}
```

1. SHIFT

```json
스택:  [ROOT, I, ate]
버퍼:  [fish]
아크:  {}
```

1. LEFT-ARC
   1. 스택 위쪽 두 항목에서 오른쪽 단어를 head로, 왼쪽 단어를 dependent로 연결
   2. dependent를 스택에서 제거

```json
스택:  [ROOT, ate]
버퍼:  [fish]
아크:  {ate ──nsubj──→ I}
```

1. SHIFT

```json
스택:  [ROOT, ate, fish]
버퍼:  []
아크:  {ate ──nsubj──→ I}
```

1. RIGHT-ARC
   1. 스택 위쪽 두 항목에서 왼쪽 단어를 head로, 오른쪽 단어를 dependent로 연결
   2. dependent를 스택에서 제거

```json
스택:  [ROOT, ate]
버퍼:  []
아크:  {
  ate ──nsubj──→ I,
  ate ──obj────→ fish
}
```

1. RIGHT-ARC

```json
스택:  [ROOT]
버퍼:  []
아크:  {
  ROOT ──root──→ ate,
  ate ──nsubj──→ I,
  ate ──obj────→ fish
}
```

**정리**

- 파서 상태 = 스택, 버퍼, 아크 집합
- SHIFT = 버퍼 맨 앞 단어를 스택으로 이동
- LEFT-ARC = 스택 위쪽 [a, b]에서 b → a를 만들고 a 제거
- RIGHT-ARC = 스택 위쪽 [a, b]에서 a → b를 만들고 b 제거
- Greedy = 매 단계 가장 좋은 후보 하나를 선택하며, 오류가 전파될 수 있음
- Beam Search = 여러 부분 분석 후보를 유지하며, 탐색 범위와 계산량 사이에 절충이 존재

가장 중요한 것 = 트리를 만드는 문제에서 → **현재 상태에서 다음 동작을 반복해서 선택하는 문제**로 바꿨다!!

## 6. 파싱 결과 평가

각 단어에 대해 파서가 맞혀야 할 것

1. Head : 어느 단어에 의존하는가?
2. 관계 라벨: 그 단어와 어떤 문법적 관계인가?

지표

| 지표                                 | 정답으로 인정하는 조건                  |
| ------------------------------------ | --------------------------------------- |
| **UAS** — Unlabeled Attachment Score | **Head가 맞으면** 정답                  |
| **LAS** — Labeled Attachment Score   | **Head와 관계 라벨이 모두 맞아야** 정답 |

- UAS = head를 맞힌 단어 수 / 평가 대상 단어 수
  - 어디에 연결했는지 << 가 맞는가?
- LAS = head와 라벨을 모두 맞힌 단어 수 / 평가 대상 단어 수
  - 어디에 연결했는지와 관계의 종류가 모두 맞는가?
- 같은 평가 대상 기준 항상 **LAS ≤ UAS**

## 7. 신경망 의존 구문 분석

핵심 : 현재 파서 상태를 보고 신경망이 다음 동작을 선택하게 한다

우리가 목차 6에서 했던 다음 동작 선택을 이제 신경망에게 맡긴다는 의미!!

신경망이 한번에 예측하는 것 = 다음 동작의 확률 !! (완성된 트리 X)

```json
현재 파서 상태
      ↓
숫자 벡터로 표현
      ↓
신경망
      ↓
SHIFT, LEFT-ARC-nsubj, RIGHT-ARC-obj, …의 확률
      ↓
선택한 동작을 실행하여 상태 변경
      ↓
다시 예측
```

**해결해야 할 문제:** 현재 상태를 어떻게 숫자로 바꿀까?

신경망: 단어 등을 임베딩 벡터로 표현 → 신경망 입력 x 생성

```json
임베딩을 연결한 x
    ↓  Wx + b₁, ReLU
은닉 표현 h
    ↓  Uh + b₂
동작별 점수 s
    ↓  Softmax
동작별 확률 p
		↓  -log p(정답동작)
손실을 이용해 모델 수정(역전파)

// 쉽게 말해 손실이 증가하는 방향의 반대로 조금 움직이는 것!
현재 파서 상태 → 동작 확률 예측 → 정답과 비교해 손실 계산
                   ↓
            역전파로 기울기 계산
                   ↓
             파라미터 업데이트
```

정리

- 상태 표현: 스택, 버퍼 등에서 선택한 단어 & 품사 & 관계 라벨의 임베딩을 이어 붙여 x 생성
- 은닉층: h = ReLU(Wx + b1)로 새로운 특징 표현 생성
- 출력층: s = Uh + b2로 동작별 점수 계산
- Softmax = 점수를 동작별 확률로 변환
- 손실 계산 - 학습 시 = 정답 동작의 확률로 L = -log p (정답) 계산
- 학습 = 역전파로 기울기를 계산하고 옵티마이저로 파라미터 업데이트

실제 문장 분석 시 보통 학습된 파라미터를 고정하고, 허용된 동작 중 하나를 선택해 실행

→ 그러면 스택, 버퍼, 아크가 변경되고 새 상태에서 다시 다음 동작을 예측

## 8. 비투사적 구조 처리

: 기본 파서가 만들 수 없는 비투사적 트리를 어떻게 처리할까?

기억할 점: 신경망의 예측이 정확해도, 파싱 동작 자체가 표현할 수 없는 구조는 만들 수 없다

그래서 `SWAP` 이라는 개념을 도입한다

| 방법                       | 핵심 아이디어                                       |
| -------------------------- | --------------------------------------------------- |
| **투사적 표현으로 단순화** | 비투사성을 다루지 않거나, 투사적인 표현 체계를 사용 |
| **후처리**                 | 먼저 투사적으로 분석한 뒤 비투사적 연결을 복원      |
| **SWAP 등 동작 추가**      | 처리 순서를 조정해 비투사적 트리를 구성             |
| **다른 파싱 방식 사용**    | 비투사적 트리를 허용하는 그래프 기반 파서 등을 사용 |

`SWAP` 동작 방식

```json
SWAP 전
스택: [..., a, b]
버퍼: [남은 단어들]

SWAP 후
스택: [..., b]
버퍼: [a, 남은 단어들]
```

정리)

- 비투사적 관계도 트리로 만들 수 있도록 SWAP이라는 동작 추가
  - 처리 순서를 조정하여 가능케 함
- 후처리로 복원
  - 먼저 투사적 구조로 분석한 뒤 비투사적 연결을 복원
- 그래프 기반 방식 사용
  - 비투사적 트리를 허용하는 알고리즘으로 전체 트리를 선택

빔 탐색과 SWAP

- **빔 탐색:** 가능한 동작 경로를 **얼마나 많이 탐색할지** 바꿉니다.
- **SWAP:** 기존 동작만으로 만들 수 없던 구조를 **만들 수 있게** 합니다.

⇒ 기본 arc-standard에 빔 탐색만 추가해도 비투사적 트리를 만들 수 있는 것은 아님 (탐색 후보를 늘려도 동작 체계의 표현 한계는 그대로이기 때문)

## 9. 후속 발전과 그래프 기반 파싱

: 어떤 연결들을 모아 트리로 만들까? 를 판단하는 것이 그래프 기반 파싱

전이 기반 파싱

- SHIFT·LEFT-ARC·RIGHT-ARC 등의 동작을 선택
- 동작을 실행하며 트리를 구성

그래프 기반 파싱

- 후보 head-dependent 연결에 점수를 부여
- 전체 점수가 높은 유효한 트리를 선택

순서

1. 가능한 연결에 점수 매기기

점수 = 해당 연결이 얼마나 적절한지 나타내는 모델의 값(확률일 필요 X)

| 분석할 단어 | 후보 head | 후보 연결     | 점수 |
| ----------- | --------- | ------------- | ---- |
| I           | ROOT      | `ROOT → I`    | 1    |
| I           | ate       | `ate → I`     | 9    |
| I           | fish      | `fish → I`    | 2    |
| ate         | ROOT      | `ROOT → ate`  | 8    |
| ate         | I         | `I → ate`     | 2    |
| ate         | fish      | `fish → ate`  | 1    |
| fish        | ROOT      | `ROOT → fish` | 1    |
| fish        | I         | `I → fish`    | 3    |
| fish        | ate       | `ate → fish`  | 9    |

1. 각 단어에서 최고 점수의 head 선택

```json
ROOT → ate    8점
ate  → I      9점
ate  → fish   9점
```

그러나 이 방법은 순환이 생길 수 있으므로 단어별 최고 점수 선택만으로는 부족

그래프 기반 파서는 트리의 조건을 만족하는 연결 조합 중에서 점수 합이 가장 높은 것을 선택해야 함

![그래프기반파서](./images/img_1.png)

수식 = 가능한 유효한 트리 T마다 연결 점수를 합산하고, 그 합이 가장 큰 트리를 선택한다

(T = 허용되는 트리들의 집합 / 비투사적 트리까지 허용하는 알고리즘을 사용하면 선이 교차하는 구조도 선택 가능)

**그럼 각 연결의 점수는 어떻게 계산할까?**

신경망 그래프 기반 파서 : 문맥을 반영한 단어 벡터 생성(같은 단어라도 문장에서 맡는 역할이 달라질 수 있으므로 주변 단어를 함께 고려해야 함)

각 단어의 문맥 벡터는 다시 2가지 표현으로 변환됨

- **Head 표현:** 이 단어가 다른 단어의 중심어가 될 때 사용할 벡터
- **Dependent 표현:** 이 단어가 다른 단어에 의존할 때 사용할 벡터

⇒ 이를 통해 `ate → fish` / `fish → ate`에 서로 다른 점수를 줄 수 있음

```json
문장
 ↓
각 단어의 문맥적 표현
 ↓
Head 표현 / Dependent 표현
 ↓
가능한 head → dependent 연결마다 점수 계산
 ↓
트리 제약을 만족하며 총점이 가장 높은 구조 선택
```

트리 선택 시 사용하는 알고리즘 ⇒ MST 계열 (루트를 기준으로 한 최대 점수 방향성 신장트리를 사용 / 비용으로 변경 시 최소화 문제로도 표현 가능)

| 방향                        | 개선하는 부분                                                                 |
| --------------------------- | ----------------------------------------------------------------------------- |
| **전이 기반 방식의 발전**   | 더 좋은 신경망, 빔 탐색, 동작 하나를 넘어 전체 동작 순서를 고려하는 학습·판단 |
| **그래프 기반 신경망 파싱** | 문맥적 표현과 biaffine 점수로 후보 연결을 평가하고 전체 트리를 선택           |

- 신경망: 각 연결이 얼마나 적절한지 평가
  ↓
- 트리 선택 알고리즘: 제약을 만족하는 최고 점수 트리 선택
