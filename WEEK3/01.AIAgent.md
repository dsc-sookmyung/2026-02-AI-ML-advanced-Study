## AI 에이전트

사용자의 요청을 해결하기 위해 LLM에 필요한 도구와 다음 행동을 선택하게 하는 시스템

### 챗봇, RAG, 에이전트 차이점

챗봇(Chatbot): 기본 형태, 입력에 대한 답변 생성

RAG(Retrieval-Augmented Generation, 검색 증강 생성): 참고 자료를 검색해 답변에 반영

에이전트(Agent): 상황에 따라 도구와 실행 흐름 선택

- 서로 배타적인 개념은 아님
- 포함 관계가 아닌 함께 쓰는 층

### 에이전트의 구성

**에이전트 = LLM + 도구 +  반복**

- LLM: 요청 해석과 행동 선택
- 도구(Tool): LLM이 호출할 수 있는 함수들, LLM이 외부 세계에 닿는 통로
    - 웹검색: 최근 정보 가져옴
    - 계산기: 정확한 수치 계산
    - DB조회: 데이터를 SQL로 끌어옴
    - 파일 시스템: PDF, CSV, 이미지를 읽고 저장
    - API 호출: 캘린더, Slack, Github, 메일 서비스 등 거의 모든 SaaS
    - 사람에게 묻기(human-in-the-loop): 위험한 작업 전 사용
- 반복(Loop): 답이 나올 때까지 반복해서 사고하는 제어 흐름

LLM은 호출할 도구와 인자를 요청함

→ 실제 함수 실행은 외부 프로그램이 담당함

### ReAct 패턴

Reasoning(추론) + Acting(행동) 번갈아 수행

**Thought → Action → Observation → 필요시 반복 → Answer**

- Thought(사고): 현재 상황 정리, 다음 행동 판단
- Action(행동): 인자로 호출할 도구 요청
- Observation(관찰): 실행 결과를 확인
- Answer(답): 최종 답변 반환

### 하이브리드 구조

모든 기능을 LLM으로 표현할 필요는 없음

- LLM: 의도 이해, 계획, 요약, 설명 ⇒ 판단이 필요한 경우
- 코드와 규칙: 정확한 계산, 검증, 권한 확인, 실행 ⇒ 확정적으로 실행하는 부분

**워크플로 자동화와 차이**

- 워크플로: 사람이 실행할 순서를 미리 설계
- 에이전트: 상황에 따라 다음 행동을 선택

→ 중요한 실행 조건은 코드로 검증, 필요한 승인을 연결

### 4가지 에이전트

1. **LongChain앱**

LCEL로 프롬프트 → LLM → 파서

- 도구 없이 LLM만을 사용
1. **RAG 챗봇**

올린 PDF를 검색 가능하게 저장하고, 질문이 오면 관련 청크를 찾아 근거로 답함

1. **웹검색 비서 에이전트**

LLM이 검색 요청 → 코드 실행 → 결과를 LLM이 읽고 요약

1. **주간 업무 리포트 + 자동 메일 발송**

SQL → 차트 → 메일

- 에이전트가 조회, 차트 요약 생성
- 코드가 메일을 검증하고 승인

### 에이전트 장/단점

**장점**

- 자연어 요청 해석
- 여러 도구 조합해 문제 해결
- 언어 중심 산출물 생성
- 정형화된 프로세스 자동화

**단점**

- 정확한 계산에는 도구가 필요
- 최신 업데이트 필요
- 같은 입력에도 결과가 달라질 수 있음
- 중요 단계는 사람 확인 필요
