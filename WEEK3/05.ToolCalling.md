## 도구 호출 (Tool Calling)

모델이 사용할 외부 도구(함수, API)와 도구를 결정하는 LLM

구조화된 요청(JSON)을 반환

도구 정의 → 도구 바인딩 → 모델 호출 → 도구 실행 → 결과 전달 → 최종 답변

### @tool로 도구 정의

Python 함수를 LangChain 도구로 변환

- 함수명 → 도구 이름
- 독스트링 → 용도 설명
- 타입 힌트 → 입력 스키마

→ 명확한 설명과 입력 정의가 도구 선택을 도움

**다른 정의 방법**

- StructuredTool.from_function(): 기존 함수로 도구 구성
    - 함수명 - 도구 이름
    - 독스트링 - 도구 설명
    - 타입 힌트 - 인자 스키마
- BaseTool 서브클래스 : 클래스로 동작을 직접 구현, DB 커넥션 풀 상태 관리가 필요한 경우

⇒ 더 정밀한 제어가 필요한 상황

- Pydantic args_schema: 인자에 상세 설명, 제약 조건 추가

### bind_tools()

사용 가능한 도구의 명세를 모델에 연결 : 바인딩 (binding)

**도구 정의 → model.bind_tools(tools) → 모델 호출**

바인딩만으로 함수가 실행되지는 않음

실행 단계

1. 전달받은 도구의 이름, 설명, 인자 스키마를 JSON Schema로 변환
2. 스키마를 LLM API 요청의 tools 파라미터에 첨부
3. 도구 호출 필요시 tool_calls + 호출 정보 반환
4. 도구 호출 필요 X시 일반 텍스트 응답 반환

**tool_choice**

- auto: 모델이 사용 여부 판단
- requred: 도구 하나 이상 사용
- none 도구 사용 차단
- 특정 도구 지정: 특정 도구의 사용을 강제

### AIMessage.tool_calls

모델이 반환한 호출 요청 목록

- AIMessage의 tool_calls 필드에 호출 정보가 담김
- 표준화된 인터페이스

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| name | str | 호출할 도구 이름 |
| args | dict | 도구에 전달하는 인자 딕셔너리 |
| id | str | 호출의 고유 식별자 |
| type | str | “tool_call” |

→ content만 읽지 말고 호출 요청을 확인해야함

### ToolMessage

실행 결과를 모델에 전달

**tool_calls 확인 → 도구 실행 → ToolMessage 생성 → 모델 재호출**

- content: 도구 실행 결과 (문자열)
- tool_call_id: 대응하는 tool_call의 id와 맞춤
- name: 도구 이름, 선택적으로 사용

### 도구 실행 루프 구현

HumanMessage 질문 → LLM의 AIMessage(tool_calls) 도구 호출 → code 도구 실행 → ToolMessage 결과 반환

while문으로 감싸서 더이상 도구를 요청하지 않을 때까지 반복

### 다중 도구 호출 처리

**여러 도구 처리**

- 한 응답에 여러 호출 요청 포함될 수 있음
    - 각 요청 실행, 각각 결과 메시지 반환
- 독립적인 작업은 병렬로 실행할 수 있음

### 에러 핸들링

에러메시지 → ToolMesaage의 content → LLM → 에러 이해 → 다른 방법 시도

try-except로 도구 실행 감싸서 에러가 발생한 도구 호출 추적

### 내장 도구와 커뮤니티 도구 활용

내장 도구: LangChain 핵심 팀이 관리

커뮤니티 도구: 외부 기여자가 생성, 관리

- langChain-core: 도구 기본 인터페이스(@tool, BaseTool)
- langchain-community: 서드파티 통합 도구
- langchain-experimental: 실험적 도구

여러 도구 조합 → 에이전트 구성→ LLM이 질문 유형에 따라 적절한 도구 선택
