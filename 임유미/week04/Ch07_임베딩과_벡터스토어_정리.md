# Ch.07 임베딩과 벡터 스토어 정리

## 학습 목표
- 임베딩 개념과 텍스트 → 벡터 변환 원리 이해
- FAISS / Chroma 벡터 스토어 설정·사용
- 검색 전략(similarity, MMR, threshold) 비교
- Retriever 인터페이스를 LCEL 체인에 연결

---

## 1. 임베딩(Embedding)

- **정의**: 텍스트를 고차원 숫자 벡터로 변환하는 기술. 의미가 비슷하면 벡터 공간에서 가깝다.
- **차원(Dimension)**: 벡터에 들어 있는 숫자 개수. 높을수록 세밀하지만 저장 공간·검색 시간 증가.
  - `text-embedding-3-small` = 1,536차원

### 코사인 유사도
- 두 벡터의 **방향**이 얼마나 같은지 측정 (크기 영향 없음)
- 공식: `dot(a, b) / (norm(a) * norm(b))`

| 값 | 의미 |
| --- | --- |
| 1.0 | 완전히 같은 의미 |
| 0.8 ~ 0.95 | 매우 유사 |
| 0.5 ~ 0.8 | 어느 정도 관련 |
| 0.0 ~ 0.5 | 거의 무관 |
| 음수 | 반대 의미 (임베딩에서는 드묾) |

## 2. LangChain 임베딩 모델

### 공통 인터페이스
| 메서드 | 입력 → 출력 | 용도 |
| --- | --- | --- |
| `embed_query(text)` | 문자열 1개 → 벡터 1개 | 검색 쿼리 |
| `embed_documents(texts)` | 문자열 리스트 → 벡터 리스트 | 문서 청크 일괄 임베딩 |

> 벡터 스토어의 `from_documents()`가 내부적으로 `embed_documents()`를 호출한다.

### OpenAI vs HuggingFace
| 항목 | OpenAI | HuggingFace (로컬) |
| --- | --- | --- |
| 비용 | 토큰당 과금 | 무료 |
| 데이터 보안 | 외부 API 전송 | 로컬 처리 |
| 설치 | `pip install`만 | torch + 모델 다운로드 |
| 속도 | 네트워크 지연 | GPU 있으면 빠름 |

### OpenAI 모델
| 모델 | 차원 | 비용(100만 토큰) | 비고 |
| --- | --- | --- | --- |
| text-embedding-3-small | 1,536 | $0.02 | 대부분 이걸로 시작 |
| text-embedding-3-large | 3,072 | $0.13 | 더 높은 정확도 |
| text-embedding-ada-002 | 1,536 | $0.10 | 레거시 (비추천) |

### HuggingFace 추천 모델
| 모델 | 차원 | 특징 |
| --- | --- | --- |
| all-MiniLM-L6-v2 | 384 | 영어, 가볍고 빠름 |
| all-mpnet-base-v2 | 768 | 영어, 높은 정확도 |
| multilingual-e5-large | 1024 | 다국어(한국어 포함) |
| BAAI/bge-m3 | 1024 | 다국어, 최신 고성능 |

### ⚠️ 흔한 실수
- **저장과 검색에 다른 임베딩 모델 사용** → 차원 불일치 오류 or 의미 없는 결과
- 모델을 바꾸면 **기존 벡터 스토어 삭제 후 전체 재임베딩** 필요

## 3. 벡터 스토어(Vector Store)

- 임베딩 벡터를 저장하고, 쿼리 벡터와 가장 유사한 벡터를 빠르게 찾는 특수 DB
- **인덱싱**: 청크 → 임베딩 → 저장(원문·메타데이터·벡터)
- **검색**: 질문 임베딩 → 유사도 비교 → 상위 K개 Document 반환
- **ANN(근사 최근접 이웃)**: 정확도를 약간 포기하고 훨씬 빠르게 검색 (FAISS, Chroma 모두 사용)

| 벡터 스토어 | 저장 방식 | 영속성 | 메타데이터 필터링 | 적합 용도 |
| --- | --- | --- | --- | --- |
| FAISS | 인메모리 | 파일 저장/로드 | 미지원(문서 기준) | 빠른 프로토타입, 대규모 검색 |
| Chroma | SQLite 기반 | 디렉토리 영속 | 지원 | 필터링 필요한 RAG |
| Pinecone | 클라우드 관리형 | 자동 | 지원 | 프로덕션 대규모 |

## 4. FAISS

```python
vectorstore = FAISS.from_documents(docs, embeddings)       # 생성
results = vectorstore.similarity_search(query, k=3)        # 검색
vectorstore.save_local(path)                               # 저장 (index.faiss + index.pkl)
vs = FAISS.load_local(path, embeddings, allow_dangerous_deserialization=True)  # 로드
vs.add_documents([new_doc])                                # 문서 추가
```

- `similarity_search_with_score()`의 점수는 **L2 거리 → 작을수록 유사** (코사인 유사도와 반대!)
- `allow_dangerous_deserialization=True`: 내부적으로 pickle을 쓰므로 필요. **본인이 저장한 인덱스만** 로드할 것.
- `vectorstore.index.ntotal`: 저장된 벡터 수

## 5. Chroma

```python
vectorstore = Chroma.from_documents(docs, embeddings, persist_directory="./chroma_db")
```

- `persist_directory` 지정 시 자동 영속 저장
- `vectorstore._collection.count()`: 저장된 문서 수

### 메타데이터 필터링
```python
vectorstore.similarity_search("LangChain", k=3, filter={"category": "langchain"})
vectorstore.similarity_search("프레임워크", k=3, filter={"year": {"$gte": 2024}})
```

| 연산자 | 의미 |
| --- | --- |
| `$eq` | 같음 |
| `$ne` | 같지 않음 |
| `$gt` / `$gte` | 초과 / 이상 |
| `$lt` | 미만 |
| `$in` | 포함 |

### ⚠️ 중복 저장 문제
- 같은 문서를 `add_documents()`로 여러 번 추가하면 **ID가 자동 생성되어 중복 저장**됨
- 해결: `ids=[...]`로 고유 ID 지정(같은 ID는 덮어쓰기) 또는 **문서 해시**로 사전 중복 확인
- FAISS는 중복 방지 기능이 없어 직접 구현 필요

## 6. Retriever & 검색 전략

- **Retriever**: 쿼리 → 관련 `Document` 리스트를 반환하는 표준 Runnable 인터페이스
- `vectorstore.as_retriever(...)`로 생성 → `retriever | prompt | model | parser` 처럼 LCEL 체인에 연결 가능

### 검색 전략 비교
| search_type | 설명 | 장점 | 단점 | 적합 상황 |
| --- | --- | --- | --- | --- |
| `similarity` | 유사도 상위 K개 | 가장 관련도 높음 | 중복 내용 가능 | FAQ, 정확한 조회 |
| `mmr` | 유사도 + 다양성 | 다양한 관점 | 관련도 약간 ↓ | 리서치, 종합 분석 |
| `similarity_score_threshold` | 임계값 이상만 반환 | 저품질 제거 | 결과 0개 가능 | 고객 응대, 의료/법률 |

### MMR 파라미터
- `k`: 최종 반환 개수
- `fetch_k`: 먼저 가져올 후보 수
- `lambda_mult`: 0 = 다양성 우선 / 1 = 관련성 우선 (= similarity) / 기본 0.5

### ⚠️ search_kwargs 실수
```python
# ❌ 직접 전달 → 에러 없이 무시되어 기본값(k=4) 적용
vectorstore.as_retriever(k=5)

# ✅ search_kwargs 딕셔너리 안에 넣기
vectorstore.as_retriever(search_type="mmr",
                         search_kwargs={"k": 3, "fetch_k": 10, "lambda_mult": 0.5})
vectorstore.as_retriever(search_type="similarity_score_threshold",
                         search_kwargs={"score_threshold": 0.8})
```

### 간단한 RAG 체인 골격
```python
rag_chain = (
    {"context": retriever | format_docs, "question": RunnablePassthrough()}
    | prompt | model | StrOutputParser()
)
```
- `k`는 3~5가 적당 (너무 크면 토큰 비용 ↑, 노이즈 ↑)

## 7. 핵심 API 정리
| API | 용도 |
| --- | --- |
| `OpenAIEmbeddings(model=...)` | OpenAI 임베딩 모델 |
| `embed_query()` / `embed_documents()` | 쿼리 / 문서 임베딩 |
| `FAISS.from_documents()` | FAISS 생성 |
| `similarity_search()` | 유사 문서 검색 |
| `similarity_search_with_score()` | 점수 포함 검색 (FAISS: L2 거리) |
| `save_local()` / `load_local()` | FAISS 저장 / 로드 |
| `Chroma.from_documents()` | Chroma 생성 (`persist_directory`) |
| `as_retriever()` | Retriever 변환 |
