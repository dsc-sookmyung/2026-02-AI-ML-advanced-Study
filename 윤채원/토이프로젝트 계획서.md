## 📝 프로젝트 개요
### 프로젝트명
대화 기억 기반 개인 맞춤형 읽을거리 추천 및 성능 비교

### 한 줄 소개
사용자의 대화 기억을 활용해 한국어 읽을거리 3개를 추천하고, 기억 방식에 따른 추천 품질과 효율을 비교하는 NLP 프로젝트

### 기획 배경 및 문제 정의
읽을거리를 추천할 때는 사용자의 관심 분야뿐 아니라 현재 목적, 선호 장르, 이미 읽은 자료 등을 함께 고려해야 합니다. 특히 “평소에는 논문을 좋아하지만 오늘은 가벼운 에세이를 읽고 싶다”처럼 장기적인 취향과 현재 요구가 다를 수 있습니다.

이때 현재 요청만 사용하면 과거 취향을 반영하기 어렵고, 전체 대화 이력을 전달하면 처리해야 할 정보가 늘어납니다. 따라서 필요한 사용자 정보를 구조화하고 관련 과거 대화를 검색하는 방식이 추천 품질과 효율에 어떤 영향을 주는지 확인하고자 합니다.

## 🎯 목표
- **핵심 목표**: 동일한 모델과 자료 목록에서 세 가지 대화 기억 방식을 비교하고, 추천 품질과 처리 효율의 차이를 분석합니다.
- **최소 구현 범위 (MVP)**:
    - 한국어 읽을거리 30개 내외의 고정된 자료 목록 구성
    - 터미널 기반 대화 및 자료 3개와 추천 이유 출력
    - 세 가지 기억 방식 구현
        - A: 현재 요청만 사용
        - B: 전체 대화 이력 사용
        - C: 구조화된 사용자 기억 + 관련 과거 대화 RAG
    - 평가용 한국어 대화 시나리오 10개 내외 구성
    - 실험 결과를 JSON·CSV로 저장하고 비교·분석
- **추가로 시도해보고 싶은 것 (Optional)**:
    - 구조화된 기억만 사용하는 비교 조건 추가
    - 사용자 정보의 위치와 대화 길이에 따른 성능 비교
    - LangGraph를 활용한 대화·기억 갱신·검색·추천 흐름 관리
    - Tool Calling 및 외부 도서·논문 검색 API 연동
    - Streamlit 기반 데모 화면 구현

## 👉 태스크 & 접근 방법
- **태스크 유형**: 
    - 대화형 추천: 사용자와 대화하며 관심사와 상황에 맞는 읽을 거리 추천
    - 정보 추출: 대화에서 관심사·선호 장르·현재 요구·읽은 자료 등의 정보 추출
    - 검색: 현재 요청과 관련된 과거 대화 기록 검색
    - 텍스트 생성: 개인화된 추천 이유와 대화 응답 생성
    - RAG: 검색한 과거 기록을 근거로 사용자 맞춤형 추천 생성
- **사용할 모델 (후보)**: 
    - Gemini 3.8 Flash: 사용자 선호 추출, 대화 기억 갱신 및 읽을거리 추천·추천 이유 생성
    - Multilingual-E5-small: 과거 대화를 임베딩으로 변환하고 현재 요청과 관련된 기록 검색
- **접근 방법**: 
    - 파인튜닝 없이 Prompt Engineering과 RAG 활용
    - 사용자 정보를 장기 취향·현재 요구·읽은 자료 등으로 구조화하고 대화에 따라 갱신
    - 과거 대화를 임베딩해 Vector DB에 저장하고 현재 요청과 관련된 기록 검색
    - 모든 방식에 동일한 자료 목록과 추천 지시문을 제공하고, 전달하는 기억 정보만 변경
    - Structured Output으로 자료 ID 3개와 추천 이유 반환
- **선택 이유**:
    - 모델을 직접 학습하지 않고도 소규모·저비용으로 구현 가능
    - 학습한 Embedding, Vector DB, RAG를 실제 프로젝트에 적용 가능
    - 단순한 추천 기능 구현을 넘어 기억 방식의 장단점을 실험으로 분석 가능

## 📏 평가 방법
- **평가 지표**: 
    - 추천 적합도: 관심사와 현재 목적에 맞는지 1~5점으로 사람 평가
    - 조건 준수율: 언어·장르·제외 조건 등 명시적 요구를 충족한 비율
    - 중복 추천률: 이미 읽었거나 제외를 요청한 자료를 다시 추천한 비율
    - 근거 정확성: 추천 이유가 자료 정보와 실제 대화에 근거하는지 확인
    - 출력 유효성: 목록에 존재하는 서로 다른 자료 3개를 반환했는지 확인
    - 효율성: 응답 시간, 입력·출력 토큰 수, LLM 호출 수 측정
- **베이스라인**: 
A: 현재 요청	현재 사용자 요청만 사용
B: 전체 대화	현재 요청과 전체 대화 이력 사용
C: 구조화된 기억 + RAG	현재 요청, 갱신된 사용자 기억, 검색한 관련 과거 대화 사용

- 모델·자료 목록·추천 지시문·생성 설정을 동일하게 유지하고, 가능한 범위에서 반복 실행
- C 방식은 기억 생성·갱신·검색에 필요한 시간과 호출량을 포함해 기록
- 가능하면 방식 이름을 가린 상태에서 사람 평가를 진행합니다.
- 기억 검색의 정확성과 최종 추천의 적합도는 구분하여 분석합니다.
