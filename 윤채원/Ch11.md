# Ch 11: LangGraph 에이전트: ReAct 패턴 구현

## ReAct (리액트)

**Re**asoning(추론) + **Act**ing(행동)의 합성어

**생각 → 행동 → 관찰**을 반복해 점진적으로 답에 접근하는 방식

단계

1. 추론 (Thought): 어떤 도구를 쓸지
2. 행동 (Action): 선택한 도구 실행
3. 관찰 (Observation): 도구 실행 결과 확인
4. 최종 답변 (Final Answer): 충분한 정보가 모이면 답변 생성

ReAct는 직선 구조인 Tool Calling과 다르게 순환 구조로 작동

### ReAct 패턴의 내부 동작 흐름

1. 사용자 질문 수신
2. LLM 추론 (agent 노드): 도구를 호출할지, 직접 답변할지 판단
3. 조건 분기
4. 도구 실행 (tools 노드): 선택된 도구 실행, 결과를 ToolMessage로 변환
5. 결과를 다시 LLM에 전달: 메시지 히스토리에 추가, 다시 2번으로
6. 최종 답변

ReAct 에이전트의 지능은 LLM이 **언제 도구를 호출할지, 언제 멈출지를 스스로 판단**하는데 있음

실제 ReAct에이전트에서는 이 과정이 프롬프트가 아닌 그래프 구조로 자동 수행

### create_react_agent: 사전 구축된 ReAct 에이전트

LangGraph가 반복을 줄이기 위해 create_react_agent()라는 사전 구축 함수를 제공

모델과 도구모델을 제공하면, ReAct 에이전트 그래프를 한 줄로 생성

**create_react_agent() 함수란?**

langgraph.prebuilt 모듈에서 제공하는 팩토리 함수

1. agent 노드 생성: LLM에 도구를 바인딩, 메시지 처리
2. tools 노드 생성: ToolNode로 도구 실행 노드 생성
3. 조건부 엣지 연결: tools_condition으로 도구 호출 여부에 따른 분기 설정
4. 순환 엣지 연결: tools→agent로 돌아가는 엣지 추가

| 파라미터 | 타입 | 설명 | 필수 여부 |
| --- | --- | --- | --- |
| model | str/ChatModel | LLM 모델 | 필수 |
| tools | list | 사용 도구 목록 | 필수 |
| prompt | str/ChatPromptTemplate | 시스템 프롬프트 | 선택 |
| checkpointer | Checkpointer | 상태 저장 | 선택 |
| state_schema | TypedDict | 커스텀 상태 스키마 | 선택 |
| response_format | type | 응답 구조화 스키마 | 선택 |

### ToolNode

LangGraph가 제공하는 사전 구축된 도구 실행 노드

AIMessage의 tool_calls 필드 읽기 → 해당 도구 실행 → 결과 ToolMessage로 변환해 상태에 추가

기능

- 도구 매칭: tool_calls의 도구 이름과 도구 리스트 매칭
- 인자 전달: tool_calls의 args를 도구 함수에 전달
- 결과 변환: 실행 결과를 ToolMessage(content, tool_call_id)로 변환
- 병렬 실행: 여러 도구 호출시 병렬 실행
- 에러 처리: handle_tool_errors=True로 예외를 변환

### tools_condition

LangGraph가 제공하는 사전 구축된 조건 판별 함수

상태의 마지막 메시지를 검사해 tool_calls가 있으aus → “tools”

없으면 → END 반환

### ReAct 에이전트

agent 노드 (LLM + bind_tools)와 tools 노드(ToolNode)가 조건부 엣지(tools_condition)으로 연결되어, tool_calls 유무에 따라 순환하거나 종료

**프롬프트가 있는 ReAct에이전트**

prompt 파라미터로 시스템에 프롬프트를 전달하면 에이전트의 행동 방식을 제어 가능

- 에이전트의 역할, 언어, 응답 스타일을 제어
- 에이전트의 품질을 높임

**도구의 description**

도구의 docstring이 모호하면 LLM이 어떤 도구를 언제 사용하는지 판단 불가능

1. 무엇을 하는지
2. 언제 사용하는지
3. 정확한 입출력 예시 명시

### **커스텀 React 에이전트**

기본 ReAct 구조만으로 부족한 경우에 에이전트의 추론 과정을 커스텀 형식으로 저장

커스텀 에이전트의 구성 요소

- 상태(State): 메시지 리스트 관리 - TypedDict + Annotated[list, add_messages]
- agent 노드: LLM 추론 수행 - bind_tools()로 LLM 호출
- tools 노드: 도구 실행 - ToolNode 또는 커스텀 함수
- 라우터 함수: 분기 설정 - tool_calls 존재 여부로 “tools” or End 반환

create_react_agent()와 차이

| 항목 | create_react_agent | 커스텀 그래프 |
| --- | --- | --- |
| 그래프 구성 | 자동 | 수동 |
| 노드 추가 | 불가 | 자유롭게 가능 |
| 반복 제한 | recursion_limit | 상태 필드로 세밀 제어 |
| 커스텀 로직 | 제한적 | 완전 자유 |

**반복 횟수 제한 추가**

에이전트가 무한 루프에 빠지는 것을 방지하기 위해 최대 반복 횟수를 설정

상태에 iteration_count 필드를 추가해 도구 호출 횟수 추적 → 제한 초과시 강제 종료

### 에이전트의 스트리밍과 중간 단계 관찰

여러번의 추론-행동 중 사용자가 빈 화면만 보고 기다리는 것은 좋지 않음

스트리밍(Streaming) 사용: 에이전트가 생각하는 과정을 실시간으로 보여줄 수 있음

→ 체감 응답 시간 크게 감소

**stream_mode 옵션 비교**

- “values”: 각 단계의 전체 상태
- “updates”: 각 단계에서 변경된 부분만
- “messages”: LLM 토큰 단위 스트리밍

### astream_events로 세밀한 이벤트 추적

비동기 환경에서 에이전트 내부의 모든 이벤트를 세밀하게 추적할 수 있는 고급 메서드

- 정밀한 디버깅과 커스텀 UI 구현
- 프로덕션 환경에서 에이전트의 동작을 모니터링
- 도구 호출 시 진행 표시줄 보여주는 UI를 구현

| 이벤트 종류 | event 필드 값 | 설명 |
| --- | --- | --- |
| LLM 토큰 생성 | on_chat_model_stream | LLM이 생성하는 각 토큰 |
| 도구 호출 시작 | on_tool_start | 도구 실행 시작 |
| 도구 호출 완료 | on_tool_end | 도구 실행 결과 반환 |
| 체인 시작 | on_chain_start | 체인/그래프 실행 시작 |
| 체인 완료 | on_chain_end | 체인/그래프 실행 완료 |
- stream() : 기본 추적
- astream_events(): 상세 추적

### 에이전트 오류 처리와 재시도 전략

오류를 적절히 처리하지 않으면 에이전트가 중간에 멈추거나, 알 수 없는 에러 메시지 표시 → 오류 처리 전략이 필수

**오류 처리 전략 비교**

- ToolNode 기본 에러 처리 (간편)
- try-except 래핑 (커스텀 에러 메시지)
- 폴백(Fallback) 도구 (안정성 높음)
- 에러 메시지 주입 (LLM이 스스로 수정)

가장 효과적인 전략 중 하나는 **에러 메시지를 LLM에 다시 전달하는 것**

에러 메시지를 LLM에 전달해 적절한 대응을 하도록 함

**모호한 에러 메시지를 LLM에 전달하면 생기는 문제**

→ 무엇이 잘못되었는지 알 수 없어 같은 실수를 반복

→ 에러의 원인, 해결 방법을 구체적으로 알려줘야함

1. 무엇이 잘못되었는지
2. 어떻게 대응해야하는지

**폴백과 recursion_limit 조합**

recursion_limit + 에러 처리 + 폴백 → 3중 안전 장치

recursion_limit으로 무한 루프 방지 → GrapRecursionError → 유용한 폴백 메시지 제공
