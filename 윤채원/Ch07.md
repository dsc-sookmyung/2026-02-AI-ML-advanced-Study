# Ch.07 임베딩과 벡터 스토어

## 임베딩(Embedding)

: 텍스트를 숫자 배열(벡터)로 변환하여 의미의 유사도를 수학적으로 계산

- 입력: 단어, 문장, 문서 등의 텍스트
- 출력: 일정한 길이의 숫자 벡터
- 두 벡터가 가까울수록 의미가 비슷함

**임베딩 동작 과정**

1. 임베딩 모델에 텍스트를 입력
2. 모델이 텍스트의 의미를 분석
3. 일정한 길이의 숫자 벡터를 출력
4. 벡터 간 거리로 유사도 계산

**차원(Dimension)**

- 벡터를 구성하는 숫자의 개수
    - ex) 384차원 → 숫자 384개로 표현
- 차원이 높은 경우
    - 세밀한 의미 표현
    - 저장 공간, 검색 시간 증가

### 코사인 유사도(Cosine Similarity): 의미적 거리 측정

두 텍스트의 임베딩 벡터가 있을 때 비슷한 정도를 측정

**두 벡터가 가리키는 방향이 얼마나 같은지**

| 값 | 벡터 사이의 관계 |
| --- | --- |
| 1에 가까움 | 방향이 비슷함 |
| 0에 가까움 | 직교에 가까움 |
| -1에 가까움 | 반대 방향에 가까움 |
- 유사도 측정에 유클리드 거리, 내적 등을 사용
- 벡터의 크기, 길이보다는 방향을 비교

### LangChain 임베딩 모델: OpenAI, HuggingFace

: 실제 텍스트를 벡터로 변환

임베딩 모델 제공업체(OpenAI, HuggingFace, Cohere 등)을 **동일한 인터페이스로 사용**

**LangChain 임베딩 인터페이스**

| 메서드 | 입력 | 출력 | 용도 |
| --- | --- | --- | --- |
| embed_query(text) | 문자열 1개 | 벡터 1개 | 질문 임베딩 |
| embed_documents(texts) | 문자열 리스트 | 벡터 리스트 | 문서 일괄 임베딩 |

**두 메서드를 구분하는 이유**

- 검색 질문과 저장 문서의 역할이 다름
- 모델에 따라 질문과 문서에 서로 다른 처리 방식이나 접두사를 사용
- 해당 모델이 요구하는 입력 형식을 따라야 함

클라우드 임베딩, 로컬 임베딩

### 벡터 스토어(Vector Store)

1. 인덱싱(Indexing): 원본 텍스트 + 메타데이터 + 변환한 벡터 값 함께 보관
2. 검색(Search): 사용자 질문을 임베딩 벡터로 변환한 후, 저장된 벡터 중 가장 가까운 K개 반환
3. 결과 반환: 유사도가 높은 순서대로 원본 텍스트(Document 객체) 반환

→ 임베딩 모델은 벡터 생성, 벡터 스토어는 저장과 검색을 담당

**ANN(Approximate Neareast Neighbor, 근사 최근접 이웃)**

: 거의 정확한 이웃을 찾는 알고리즘

벡터 공간을 여러 구역으로 나눠 해당 구역만 검색

- FAISS
- Chroma

### FAISS: 인메모리 고속 벡터 검색

Meta에서 개발한 오픈소스 벡터 검색 라이브러리

- 수백만 개의 벡터에서 밀리초 단위로 유사한 벡터 검색
- LangChain에서 사용하는 주요 메서드

**기본 사용법**

1. 문서 준비
2. 벡터 스토어 생성: `FAISS.from_documents(docs, embeddings)`
3. 유사도 검색: `similarity_search(query, k=4)`
4. 저장/로드: `save_local()` , `load_local()`

**유사도 점수**

- 유사도 점수는 거리(L2 거리)로 표현
- 값이 작을수록 유사도가 높음 (코사인과 반대)

**인덱스 저장, 로드**

FAISS는 인메모리 기반 → 프로그램 종료 시 데이터 사라짐

save_local(), load_local()로 디스크에 영속화 가능

### Chroma: 영속성 있는 벡터 데이터베이스

문서, 벡터, 메타데이터를 관리하는 벡터 데이터베이스

- 메모리에서 실행 가능
- persist_directory를 지정해 디스크에 데이터 자동 저장
- 문서 추가, 수정, 삭제 지원
- 메타데이터 조건과 유사도 검색 결합 가능

**메타데이터 필터링**

벡터 유사도 검색 + 메타데이터 조건 → 더 정확한 결과

- ‘특정 카테고리만’: 의미적으로 무엇을 찾을지
- filter: 어떤 문서에서 찾을지
- k: 반환받을 문서 수

필터를 적용해 문서의 조건을 판단, RAG 시스템의 검색 품질을 향상시킴

### Retriever 인터페이스와 검색 전략

: 자연어 쿼리를 입력받아 관련 문서 목록을 반환하는 표준 인터페이스

LCEL 체인 (retriver | prompt | model | parser) 형태로 검색과 생성을 하나의 체인으로 연결하기 위해 사용

1. FAISS, Chroma 벡터 스토어: as_retriever() 지원
2. 벡터 스토어를 Runnable 인터페이스의 Retriever로 변환
3. 문자열 쿼리를 받아 Document 리스트 반환
4. Retriever이 LCEL 체인에서 다른 컴포넌트와 연결

**검색 전략 비교**

search_type 파라미터로 검색 전략 선택

| 검색 전략 | 선택 기준 | 주의점 |
| --- | --- | --- |
| similarity | 코사인 유사도 상위 k개 반환(관련도 높은 결과) | 비슷한 내용 중복 가능 |
| mmr | 유사도 + 다양성 균형 (다양한 결과) | 다양성을 높이면 관련성이 낮아질 수 있음 |
| similarity_score_threshold | 유사도 임계값 이상만 반환(저품질 제거) | 결과가 적거나 없을 수 있음 |

**MMR**(Maximal Marginal Relevance, 최대 한계 관련성)

: 관련성은 높되 서로 다른 내용의 문서를 선택

lambda_mult 파라미터

- 관련성과 다양성의 균형을 조절
- 기본값 = 0.5
- 1에 가까우면 관련성 우선, 0에 가까우면 다양성 우선
